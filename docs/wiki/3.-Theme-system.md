# Theme system

Themes are discovered from folders in `resources/themes/`. Atom ships `atom` and `dusk`. The folder name is both the theme ID and its label; use lowercase letters, digits and single hyphens, starting with a letter. The IDs `all`, `core`, `housekeeping` and `vendor` are reserved. Each theme uses its own `theme-<id>::` namespace for views and components.

Installer and reset mail are explicit Core views under `resources/views/core`, outside public themes. A page view the route requests that the theme omits returns 404. A view missing while a page renders (a layout, partial or Livewire view), or an invalid definition returns the Core 503 diagnostic. Omitting a template does not disable backend actions or change permissions. Housekeeping, the installer, the API and payment callbacks remain independent. See the [installation and deployment guide](1.-Installing-Atom-CMS.md) for custom installer/mail override upgrade paths.

Themes only apply in full mode. In [headless mode](10.-Headless-mode.md) there is no public theme.

Build the target theme with `npm run build:atom` or `npm run build:dusk`. During development use `npm run dev:atom` or `npm run dev:dusk`.

To scaffold a custom theme:

```bash
php artisan make:theme my-theme
```

The command comes from the installed `qirolab/laravel-themer` package and creates a starting directory. Provide the theme's own views and name its components as `<x-theme-my-theme::â€¦>`. Decline replacement authentication scaffolding unless replacing that integration is intentional; Atom's existing authentication and controllers support the hotel's features.

Themes may use Core's shared, non-visual pieces instead of copying them: `<x-core::seo-meta />` for the page title and meta tags, `<x-core::fancybox-assets />` for the Fancybox scripts, `\App\Support\FlashToasts::from(session()->driver(), $errors)` for the flashed toast messages and `\App\Support\FooterCredits::contributors()` and `translators()` for the translated credits. Markup and styling stay in the theme.
