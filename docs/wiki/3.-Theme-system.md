# Theme system

Themes are discovered from folders in `resources/themes/`. Atom ships `atom` and `dusk`. The folder name is both the theme ID and its label; use lowercase letters, digits and single hyphens, starting with a letter. The IDs `all`, `core`, `housekeeping` and `vendor` are reserved. Each theme uses its own `theme-<id>::` namespace for views and components.

Installer and reset mail are explicit Core views under `resources/views/core`, outside public themes. A page view the route requests that the theme omits returns 404. A view missing while a page renders (a layout, partial or Livewire view), an invalid definition or an unavailable essential build returns the Core 503 diagnostic. Omitting a template does not disable backend actions or change permissions. Housekeeping, the installer, the API and payment callbacks remain independent. See the [installation and deployment guide](1.-Installing-Atom-CMS.md) for custom installer/mail override upgrade paths.

Themes only apply in full mode. In [headless mode](10.-Headless-mode.md) there is no public theme.

Build the target theme before changing the `theme` value through Housekeeping's CMS settings:

```bash
npm ci
npm run build:all
```

`build:all` builds both themes and the shared targets. To build one theme, use its build command and build Core and housekeeping separately. `php artisan build:theme` offers an interactive selection. During development use `npm run dev:atom` or `npm run dev:dusk`.

Theme outputs are independent: `public/build/themes/atom` and `public/build/themes/dusk`. `build:atom` and `build:dusk` build only their respective theme, preserving the other's output. `build:core` and `build:housekeeping` build shared outputs separately; `build:all` builds each target once. Development markers are `storage/vite/atom.hot` and `storage/vite/dusk.hot`; `npm run dev:core` and `npm run dev:housekeeping` use `storage/vite/core.hot` and `storage/vite/housekeeping.hot`.

To scaffold a custom theme:

```bash
php artisan make:theme my-theme
```

The command comes from the installed `qirolab/laravel-themer` package and only creates a starting directory: provide its own views and name its components as `<x-theme-my-theme::…>`. Review its generated files and add the `dev:my-theme` and `build:my-theme` scripts it prints to `package.json`. Follow the shared [theme Vite configuration](../../resources/js/theme-vite.config.js) for asset paths and manifests. Decline replacement authentication scaffolding unless replacing that integration is intentional; Atom's existing authentication and controllers support the hotel's features.

Themes may use Core's shared, non-visual pieces instead of copying them: `<x-core::seo-meta />` for the page title and meta tags, `<x-core::fancybox-assets />` for the Fancybox scripts, `\App\Support\FlashToasts::from(session()->driver(), $errors)` for the flashed toast messages and `\App\Support\FooterCredits::contributors()` and `translators()` for the translated credits. Markup and styling stay in the theme.

In the theme's `vite.config.js`, import `createThemeConfig` from the shared [theme Vite configuration](../../resources/js/theme-vite.config.js) and export `createThemeConfig(__dirname)` to use `css/app.css` and `js/app.js` as inputs. These are the conventional entrypoints loaded by `theme_vite()` in development and production; import additional CSS and JS from them. A valid folder makes the theme discoverable. Build the custom theme, set its ID as the CMS `theme` through Housekeeping, and check the login, registration, user settings, client, shop and housekeeping flows. Use the shared [settings guidance](README.md#changing-settings) when making database changes outside Housekeeping.

For unavailable media, `theme_asset()` logs the missing asset and returns a URL in the selected theme's build directory so the browser can handle the missing file. Production deployments need compiled output and views, not original JS/CSS/media sources; building requires source entrypoints. `php artisan atom:mode --status` reports invalid themes as diagnostics and does not require public theme files in headless mode.
